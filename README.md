# Lead Dispatcher

Управляющий Telegram-бот принимает карточки с фотографией и подписью, подключает рабочие Telegram-аккаунты, читает историю выбранного канала от новых сообщений к старым и ведёт очередь. Адресат определяется по @username или российскому номеру телефона. Для номера делается один запрос `contacts.resolvePhone` без добавления в контакты. Если пользователь не найден, карточка сразу записывается в ненайденные.

## Интерфейс

После `/start` доступны кнопки:

- **Аккаунты** — вход по номеру с кодом и паролем двухэтапной проверки либо через QR; выбор и удаление сохранённой сессии.
- **Канал** — выбор из каналов аккаунта либо ввод ссылки, @username или ID.
- **Сканировать** — чтение всех фото-публикаций канала, загрузка фото и добавление карточек в очередь без повторов.
- **Очередь** — статус и ближайшие карточки.
- **Тест себе** — после подтверждения отправка одной пересланной карточки с парой сообщений только на адрес из серверной переменной `LEAD_DISPATCHER_TEST_RECIPIENT`.
- **Ненайденные** — записи без контакта/фото, номера, которые Telegram не раскрыл, и повторы адресатов.
- **Пауза/Запуск** — управление рассылкой. Кнопка запуска действует только при включённом серверном `LEAD_DISPATCHER_ALLOW_SEND=1`.

## Отчёты в группе

Добавьте бота в нужную группу и отправьте там `/reports_here` **от аккаунта оператора**, указанного в `TELEGRAM_ADMIN_CHAT_ID`. Бот ответит «Отчёты будут здесь» и сохранит ID группы. Без привязанной группы кампания не запускается.

После каждой успешной пары сообщений бот пишет в группу исходный @username или телефон карточки и счётчик отправок по выбранному каналу. Если адресат не найден, нет фото, обнаружен повтор или отправка завершилась ошибкой, бот пишет короткий отчёт с причиной. Отчёты хранятся в SQLite до доставки в группу; при недоступности группы обработка следующих карточек приостанавливается. При завершении очереди бот отправляет итоговый счётчик и список всех пропущенных карточек, разбитый по причинам. Пересланная оператором тестовая карточка не входит в счётчик выбранного канала.

Оператор определяется строго по `TELEGRAM_ADMIN_CHAT_ID`. Коды и пароли не сохраняются: бот пытается удалить сообщения с ними из чата. Сессии аккаунтов находятся в приватной SQLite-базе, а не в репозитории. Доступ к серверу и к личному чату управляющего бота должен быть ограничен.

При разрешённой отправке для каждого нового адресата отправляется сохранённое фото с одним из трёх первых текстов из `config.example.json`, затем отдельное «Вы тут на связи?». Первое приветствие выбирается по Москве: с 04:00 до 10:59 — «Доброе утро», с 11:00 до 17:59 — «Добрый день», с 18:00 до 03:59 — «Добрый вечер». Между парами выдерживается случайная пауза 50–70 минут. Перед отправкой создаётся запись в `deliveries`; сбой или перезапуск во время отправки не приводит к автоматическому повтору, такая карточка требует проверки. Уже обработанный адресат пропускается.

В рабочую рассылку попадают только карточки выбранного и просканированного канала. Пересланные оператором в личный чат бота образцы остаются в тестовой базе и не отправляются адресатам.

## Развёртывание

Python 3.10+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN='...'
export TELEGRAM_ADMIN_CHAT_ID='...'
export TELEGRAM_API_ID='...'
export TELEGRAM_API_HASH='...'
export LEAD_DISPATCHER_DB='data/queue.sqlite3'
export LEAD_DISPATCHER_CONFIG='config.example.json'
.venv/bin/python bot_control.py
```

Храните переменные окружения в файле с правами 600, вне Git. Каталог `data/` также должен быть доступен только пользователю сервиса. По умолчанию отправка лидам **выключена**, даже если нажать «Запуск». Для последующего разрешения владелец должен отдельно включить `LEAD_DISPATCHER_ALLOW_SEND=1` на сервере и нажать «Запуск».

Командный интерфейс для проверки данных: `python lead_dispatcher.py preview`, `python lead_dispatcher.py export-unresolved data/unresolved.csv`, `python telegram_adapter.py --channel ...`.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

## Связи и границы проекта

Бот читает карточки лидов из Telegram-канала, ищет адресата по `@username` или телефону, ставит отправку в очередь и доставляет карточку через рабочий аккаунт. Заявки на вступление в каналы обрабатывает отдельный `tg-auto-approve-bot`.
